# Web UI

The Next.js "Mission Center" in `weebot-ui/` (`npm run dev`, `weebot-ui/package.json` scripts; `next dev -H localhost` and `next start -H 127.0.0.1`, `weebot-ui/package.json:6, 8`). It talks to the FastAPI backend over REST (through a same-origin proxy) and WebSockets (direct to the backend).

## Why this shape
REST goes through `/api/...` on the Next server so the browser stays same-origin; the catch-all route handler forwards to the backend (`weebot-ui/src/app/api/[[...path]]/route.ts:5-58`). WebSockets cannot go through that handler, so they connect to the backend directly (`weebot-ui/next.config.mjs:29-30` comment, `src/lib/endpoints.ts:1-33`). Backend URLs live in one file, `src/lib/endpoints.ts`, from `NEXT_PUBLIC_API_URL` / `NEXT_PUBLIC_WS_URL` (`:30-33`), overridable per browser by `localStorage` `weebot_backend_url` / `weebot_ws_url` (`src/lib/api.ts:3-13`, `src/providers/EventStreamProvider.tsx:84-98`). The API key is kept in `sessionStorage` `weebot_api_key` (`src/lib/api.ts:15-23`); `authHeaders()` attaches it to calls made outside `fetchApi` (`weebot-ui/src/lib/api.ts:25-29`), and `openSocket()` sends it as a WebSocket subprotocol (`:31-47`) and, for a key the constructor refuses as a subprotocol token, opens without it instead of throwing.

## Shape
Pages (`src/app/`): `/` composer (`weebot-ui/src/app/(console)/page.tsx:16-27`), `/sessions` list, `/sessions/[id]` conversation (`weebot-ui/src/app/(console)/sessions/[id]/page.tsx`), `/ops` health, metrics, active sessions and a live log, `/models`, `/behavior` (monitor and settings tabs), `/settings` backend URLs, `/settings/behavior` redirect to `/behavior?tab=settings` (`settings/behavior/page.tsx:8-10`), `/debug` WebSocket tester. `layout.tsx:35-47` wraps all pages in Theme, Toast, `EventStreamProvider`, a tooltip provider, `AnnouncerProvider` and `ShellProvider`, and renders them inside `AppShell`.

## Frame and state (UI/UX plan, 2026-10-24)
- **One frame.** `AppShell` is the window (`h-dvh`): skip link, `AppBar` (the single 48 px header; below `lg` the nav and actions sit behind a menu `Dialog`), the only `<main id="main-content">`, and the command palette (`weebot-ui/src/components/shell/AppShell.tsx:17`, `AppBar.tsx:28`). A page fills the bar's title and connection slots, and names the session whose dock to show, with `useShellSlots` (`src/hooks/useShellSlots.ts:7`, `src/providers/ShellProvider.tsx:29`); pages own no chrome.
- **One console, mounted once.** The `(console)` route group holds `/` and `/sessions/[id]` under `app/(console)/layout.tsx`, which renders `ConsoleShell` (rail, content, dock; `src/components/shell/ConsoleShell.tsx:21`), so the rail and its data survive navigation. Below `md` the rail and dock are side sheets on the `Dialog` primitive (`ResponsivePanel`, `src/components/shell/ResponsivePanel.tsx:24`; `DialogSheet` in `src/components/ui/dialog.tsx`).
- **Async data is a type.** `Remote<T>` (`src/types/remote.ts`) is loaded by `useRemote` (`src/hooks/useRemote.ts`) and drawn by `StateView` (`src/components/common/StateView.tsx:24`): skeleton, error with Retry over stale data, empty, ready. `useRemote` drops a response older than one already shown (the newest wins). `useSessionList` and `/sessions` use it (`src/hooks/useSessionList.ts:28`); `useSessionList` drops rows whose presence status is `deleted` (`:35-43`). `/ops` health and metrics load through it independently (`weebot-ui/src/app/ops/page.tsx:67-68`). Toasts take ids from a ref and pause their clock while hovered or focused (`src/providers/ToastProvider.tsx:54, 104-110`); the theme is read with `useSyncExternalStore` (`src/providers/ThemeProvider.tsx:49`).
- **One status component.** `statusInfo` maps a status to label, icon and tone (`src/components/common/status.ts:43`); `StatusBadge` draws it, so status is never colour alone. Text colours use the `--status-*-fg` tokens, which meet 4.5:1 (`scripts/check_ui_contrast.py`).
- **Conversation.** `useStickToBottom` pins the timeline with an `IntersectionObserver` and counts unseen rows (`src/hooks/useStickToBottom.ts:14`); the timeline is a `role="log"` that is not a live region, and coarse moments go through `AnnouncerProvider` (`src/lib/announce.ts`). The composer is a reducer (`src/lib/composer.ts`) behind `useComposer` (`src/hooks/useComposer.ts`): never disabled while sending, per-session draft in `sessionStorage`, IME-safe Enter. Optimistic user messages carry `delivery` (`sending|sent|failed`); the server echo (same id) settles them, and wins over a late failure: `markDelivery` never downgrades a `sent` row (`src/lib/session-reducer.ts:64, 110-117`). `ConversationPane` merges the fetched history with live rows through `mergeHistory` (`:131`), settles sends through `settleDelivery` (`src/components/conversation/ConversationPane.tsx:103`) and draws only event types in the registry (`isRendered`, `EventRenderer.tsx:38`). `useComposer` toasts a failed run start, and offers retry for a failed send (`src/hooks/useComposer.ts:81-108, 129`). Tool rows show arguments, a failed state from the backend's `ToolEvent.is_error`, copy, and the full result on request.
- **Lazy heavy views.** reactflow loads on demand through `LazyPlanVisualizer`, recharts through `next/dynamic` in `/ops` (`src/components/plan/LazyPlanVisualizer.tsx`).
- **Backend facts the UI shows.** The session title is the stored one, else derived from the prompt (`weebot/domain/services/session_title.py`, `weebot/interfaces/web/routers/sessions.py` `_displayed_title`); `event_count` comes from `EventStorePort.count_events`; the planner's `TitleEvent` replaces the derived title (`weebot/application/services/task_runner.py`).

Backend calls:
- `src/lib/api.ts:49-92, 127-228` (`fetchApi` adds `X-API-Key`; only a failed `fetch()` is "cannot connect", a non-2xx body is read for `detail` (a FastAPI 422 list is joined) or `error`): sessions list/create/get/events/delete/cancel/run/resume/input, models list/available/roles/setRole/resetRole, health check/ready/live, dashboard metrics, ops activeSessions/planViz/costSummary. Used: list, create+run on first message, input after that (`weebot-ui/src/hooks/useComposer.ts:78-99`), get+events (`weebot-ui/src/app/(console)/sessions/[id]/page.tsx:43-57`), cancel (`components/conversation/RunControls.tsx:24`), delete, models list, per-role model picks (`components/models/RoleModelsPanel.tsx:91-97`), health, dashboard metrics, activeSessions, planViz, costSummary (`components/dock/CostTab.tsx:21`).
- Proxy (`route.ts`): target `BACKEND_URL` or `ENDPOINTS.api` (`:5`); refuses a non-same-origin POST/PUT/PATCH/DELETE with 403 (`:17-19`, policy in `lib/proxy-guard.ts`); forwards the client's `Content-Type`, `X-API-Key` and `Authorization` (`:25-35`); relays the upstream bytes and `content-type`, with a null body for 204, 205 and 304 (`:45-51`).
- Live events (`EventStreamProvider.tsx`): one socket per session to `{ws}/sessions/{id}`, the key sent as the `bearer.<key>` subprotocol by `openSocket` (`src/lib/api.ts:36-47`), not in the URL (`:181-226`), reference-counted; after 5 failed reconnects falls back to `fetch` of `/api/events/stream` filtered by `session_id` client-side (`:120-179`). One global socket to `{ws}` for `session_presence` events only (`:263-296`), consumed by `useSessionPresence` / `useSessionList` (`src/hooks/useSessionPresence.ts`, `src/hooks/useSessionList.ts`).
- Behavior: socket `ENDPOINTS.behaviorWs` (`/api/behavior/ws`, or `/session/{id}`) with `openSocket` (`weebot-ui/src/hooks/useBehavior.ts:69-74`); REST `trust`, `recent`, `override` through `getApiBase()` (the proxy unless a backend URL set) with `authHeaders()` (`:184-232`); `RecentActions.tsx` posts `override` the same way and shows a refusal or an unreachable backend in an alert (`weebot-ui/src/components/behavior/RecentActions.tsx:52-76`); `app/behavior/page.tsx` calls only `/api/behavior/self-knowledge` through the proxy (`weebot-ui/src/app/behavior/page.tsx:96`). The settings tab has no settings API; it lists the environment variables (`:93-94, 132-141`).
- `/ops` opens a socket to `{ws}` (with `openSocket`) for its log view; the caption follows `onopen` and `onclose`, and it reconnects after 3 s (`weebot-ui/src/app/ops/page.tsx:40-44, 76-109, 323-325`).

Consequences (read from source, not run):
- The proxy forwards from the Next server, so the backend sees a loopback client. `authenticate` admits a loopback caller as anonymous when no key is configured (`weebot/interfaces/web/auth.py:236`), and `require_mutation_identity` lets an anonymous loopback caller mutate unless `WEEBOT_BEHIND_PROXY` is on, which is off by default (`auth.py:55-64, 276-289`; `.env.example:189`). The Docker image binds the Next server on `0.0.0.0:3000` (`weebot-ui/Dockerfile:41-44`). `npm run dev` / `start` bind loopback only (F45), but with no `WEEBOT_API_KEY` and that flag off, any client that reaches port 3000 of the Docker image gets loopback rights on `/api/*`.
- The proxy buffers the whole upstream body (`route.ts:46`), so it relays text such as `/api/health/prometheus` with its content type, but a stream (`/api/chat/stream`, `/api/events/stream`) arrives only once it ends. The SSE fallback fetches `ENDPOINTS.api` directly.
- `/ops` "live log" listens on `/ws`, which only receives events without a `session_id` (`weebot/interfaces/web/event_broadcaster.py:37-46`), so it shows presence events, not session activity; the backend sends a presence frame only to its session's owner when ownership is enforced (`WebAPI.md`).
- Socket keys travel as the `bearer.<key>` subprotocol, not the query string: every socket opens through `openSocket` (`EventStreamProvider.tsx:189, 268`, `useBehavior.ts:74`, `weebot-ui/src/app/ops/page.tsx:83`, `weebot-ui/src/hooks/useWebSocketDebug.ts:44`). The backend refuses a `?token=` (decision D2, `weebot/interfaces/web/auth.py:76-99`). The SSE fallback sends `X-API-Key` (`EventStreamProvider.tsx:128-131`).
- `next.config.mjs:23-28` also rewrites `/api/:path*` to a hard-coded `http://localhost:8000`, a second routing rule beside the route handler that ignores `BACKEND_URL`.
- Backend endpoints with no UI caller: all of `/api/chat/*`, `/api/sessions/search`, `/api/sessions/{id}/steer`, `/api/sessions/{id}/resume` (`api.sessions.resume` is defined, unused), `/api/ponytail/*`, `/api/models/available`, `/api/health/ready` and `/live` (defined in `api.ts:192-193`, unused), behavior `watch/*`, `report/*`, `session/{id}`, `self-knowledge/regenerate`, `/api/webhook/run` (machine caller).

## Connected to
- **Calls** the Web API (`WebAPI.md`). **Owns** no backend state; per-browser settings only.
- **Types** mirror backend events in `src/types/events.ts`; the session reducer is `src/lib/session-reducer.ts`.
- **Looks like but is not:** the test page the backend serves at `/` (`weebot/interfaces/web/main.py:76-177, 617-620`).
