# model cascade

**Input:** the executor's message list and the step description, once per tool-loop turn (`weebot/application/agents/executor/_turn.py:54-56`) and once for the budget-cap summary (`weebot/application/agents/executor/_base.py:591-593`).
**Movement:** pick a role cascade from `ROLE_MODEL_CONFIG`, add the pinned model and the step's category model, filter by OpenRouter credit and the session cost limit, hedge probes one at a time, fall back sequentially, then try a live rescue on all-404.
**Output:** one `LLMResponse`, a `CascadeDecision` per attempt, an `LLMCallCompleted` domain event per success; or `AllModelsTrippedError` (or `SessionBudgetExceededError` before any attempt, once the session's hard cost limit is reached, `_cascade.py:542-551`).

## Steps
1. **Construction.** Each `ExecutorAgent` builds its own `CascadeExecutor` with `agent_role=agent_role or "executor"`, `model_provider=self._resolve_model_for_step`, the DI `llm_pool`, `provider_account`, `pinned_model` and `cost_meter`, `on_success` = the context compressor's usage tracker, and `on_call_completed=self._publish_llm_call` (`_base.py:169-188`). Pool, account and cost meter come from `weebot/application/di/__init__.py:501-502, 508`; the pinned model from `StepExecutionContext` (`weebot/application/models/step_execution_context.py:31`; `di/__init__.py:513`).
2. **Role cascade.** `get_model_cascade_for_role(self._agent_role)` (`weebot/application/agents/executor/_cascade.py:556`; `weebot/config/model_refs.py:143-160`): the role's list in `ROLE_MODEL_CONFIG` (`model_refs.py:102-135`), or `_DEFAULT_ROLE_CASCADE` for None or an unknown role (`model_refs.py:137, 149-153`). An Ollama model for the role goes first when enabled, then a free-tier model when WEEBOT_FREE_ROLES lists the role (`model_refs.py:154-155, 172-196`; `weebot/config/free_models.py`), then the user's UI pick from `role_overrides` (`model_refs.py:157-160`). `build_cascade_plan` orders the whole list (`weebot/core/cascade_plan.py:29-50`, called at `_cascade.py:598-605`): phase 1 takes the primary and fallback 1, phase 2 takes every later entry in order and then `MODEL_CASCADE_TIER4`; a list shorter than that falls back to `MODEL_CASCADE_TIER2` / `TIER3`. The tier constants are at `model_refs.py:31-41`, the premium set at `model_refs.py:140`.
3. **Step model.** `model_provider(description)` (`_cascade.py:559-566`): a screenshot in the buffer forces `[MODEL_VISION_PRIMARY]` once (`_base.py:332-347`); with `WEEBOT_ENABLE_ACR` (on by default) it returns the top two of the shared `AdaptiveCapabilityRouter`'s ranking (DI key `ACR_ROUTER`, `di/__init__.py:349-363`), whose stored posteriors are loaded before routing (`_cascade.py:553-554`) and updated from every call's outcome (`weebot/application/services/routing/adaptive_capability_router.py:231`); otherwise `[model_for_step(description)]` (`_base.py:349-376`), which is the first model of the role mapped to the step's `TaskCategory` (`weebot/application/services/task_model_router.py:22-36, 185-188`; classifier `weebot/application/services/task_model_router.py:150-182`). That lookup reads `ROLE_MODEL_CONFIG` directly, so Ollama and UI overrides do not apply to it. The category is also classified for telemetry, cached per description for the process (`_cascade.py:87, 128-146, 567`).
4. **Credit filter and budget.** Candidates are the pinned model, role primary, ACR list, task model and fallback 1, deduplicated (`_cascade.py:598-606`). With an OpenRouter balance below `OPENROUTER_MIN_CREDIT_USD` (default 0.10), OpenRouter-only models are dropped; unknown balance filters nothing (`_cascade.py:190-219`, threshold `_cascade.py:67-85`; direct-provider prefixes `_cascade.py:186`). Past the session's soft cost limit PREMIUM models are dropped unless that would empty the list (`_cascade.py:509-521`, called at `_cascade.py:606`).
5. **Phase 1, hedged probes.** One probe starts (90 s); the next starts when it fails or after `_HEDGE_DELAY_S` = 20 s (`_cascade.py:69, 610-650`). The loop waits for a probe that succeeds, not the first to finish (`_cascade.py:653-665`). All still-pending probes are cancelled on every exit, with a 5 s bound (`_cascade.py:666-681`), and each cancelled probe that had sent its request is billed as an estimate (one still queued for an `llm_pool` slot sent nothing and is not billed) (prompt tokens only, `LLMCallCompleted.estimated`) by `_call_unanswered` (`_cascade.py:276-283`), because a cancelled non-streamed request still bills. Each attempt holds an `llm_pool` slot before its clock starts (`_cascade.py:314-355`) and calls `llm.chat` with `tools=self._tools.to_params()` (`_cascade.py:398-411`), so per-step tool scoping applies.
6. **Per-attempt bookkeeping.** Usage is read and `_call_completed` awaited as soon as `chat` returns, for any response, so an empty reply that carries usage is metered too (`_cascade.py:412-422`). Success then resets the model's breaker and records a SUCCESS decision with a cost estimate (`_cascade.py:423-443`); the success path reads `cached_tokens` from the usage and prices them at `CACHE_READ_FRACTION` of the input rate; an empty answer records FAILED and counts toward the breaker (`_cascade.py:444-455`); a timeout records FAILED, counts toward the breaker like any failure and is billed as an estimate (`_cascade.py:456-469`); other errors record `first_error`, count toward the breaker (trips at 5, `_cascade.py:72, 155-165, 475-478`) and mark 5xx models to skip for the rest of the run (`_cascade.py:485-488`). A fast-fail error (`ErrorClassifier.should_fail_fast`: auth, bad request) skips the model for the run, without the breaker or `first_error` (`_cascade.py:471-480`). The shared `fast_fail` flag is set when any `first_error` text classifies as a bad key or a missing model through `ErrorClassifier` (`_is_fast_fail_error`, `_cascade.py:303-311`; set at `_cascade.py:589-594`); it cuts the remaining timeouts to 15 s (`_cascade.py:387`).
7. **Phase 2, sequential.** Every role-list entry from the third on, then `MODEL_CASCADE_TIER4`, 60 s each, skipping tripped, already-probed and 5xx models (`_cascade.py:688-702`); both phases drop free tiers that train on prompts once the session is tainted (`keep_private`, `weebot/application/agents/executor/_session_scope.py:167`).
8. **Live rescue.** Only when `fast_fail` was set and every recorded first error classifies as a missing model (`MODEL_UNAVAILABLE`: a standalone 404 or a model-not-found message, `_cascade.py:704-717`): `_live_model_rescue` lists models from the provider account, keeps tool-capable ones allowed by `claude_model_allowed`, prefers paid over `:free`, ranks by context of at least 128k, then catalog price, then context, and tries the first under the pool with a 30 s timeout (`_cascade.py:726-801`).
9. **Terminal.** Otherwise `AllModelsTrippedError(ALL_MODELS_TRIPPED_MESSAGE)` (`_cascade.py:720-722`); the message (`_cascade.py:44-48`) names the API key, the model names and the account credits, and its first sentence is what `_all_models_tripped` matches to skip a replan (`weebot/application/flows/states/_step_outcome.py:164-176`). The executor turns `LLMCapacityExhaustedError` from the pool into an `ErrorEvent` and a message (`_turn.py:57-75`).
10. **Usage reporting.** `_call_completed` builds `LLMCallCompleted(model, tokens, cost=_estimate_cost(...))` (`_cascade.py:247-274`); `_publish_llm_call` stamps the session id and publishes it as a domain event (`_base.py:314-319`). `on_success` feeds the context compressor (`_base.py:184`). After the step, `ExecuteStepHandler` returns `executor.token_usage` (`weebot/application/cqrs/handlers/execute_step_handler.py:37-41, 158`), which the flow adds up in `record_step_usage` (`weebot/application/flows/states/_step_run.py:89`; `weebot/application/flows/plan_act_flow.py:616-620`).

Consequences (read from source, not run):
- The `model` the flow sends with `ExecuteStepCommand` (`--model` or `MODEL_BUDGET`, `_step_run.py:75`) is stored on the executor (`_base.py:115`) and used by the context compressor (`_context_compressor.py:40`). The cascade sees only the flow's own model, and only when set: `pinned_model=self._model or None` (`plan_act_flow.py:605-614`), tried first (`_cascade.py:603`).
- On the `flow run` path no profile is set (`weebot/interfaces/factories.py:228`; `weebot/application/flows/flow_builder.py:95`), so `agent_role` is None and `ExecutorAgent` substitutes `"executor"` (`_base.py:173`): steps use `ROLE_MODEL_CONFIG["executor"]` (`model_refs.py:112`), not `_DEFAULT_ROLE_CASCADE`.
- Fast-fail errors are written to the tracker as FAILED even though they skip the breaker (`_cascade.py:471-480, 486-494`).
- Probe and fallback tiers are labelled per model by `_tier_of`: `:free` is FREE, `PREMIUM_MODELS` is PREMIUM, else BUDGET (`_cascade.py:501-507, 623, 696`). Telemetry only.
- The `fast_fail` flag never comes from the fail-fast branch, which skips `first_error` (`_cascade.py:471-480, 588-593`), so an auth failure alone does not shorten later timeouts.

## If you change this
**Hits:** every executor LLM call (all flows that run steps), `ModelCascadeTracker` / ACR telemetry, cost accounting through `LLMCallCompleted`; `ROLE_MODEL_CONFIG` is shared with DI's per-role LLMs, the context switcher and the role selector (`model_refs.py:72-75`); tests `tests/unit/test_cascade_executor.py`, `tests/unit/test_model_cascade_tracker.py`.
**Does not hit:** the planner's model choice (`PlannerAgent`, through `CreatePlanCommand.model`, `weebot/application/flows/states/planning.py:247`); `weebot/core/model_cascade_config.py`, which only supplies `estimate_cost` (`_cascade.py:14` imports it as `_estimate_cost`).
