## D47 — there was no configuration in which MCP authentication worked

The claim was half the picture. Without a key the server is unauthenticated;
**with** a key it did not start. Six defects in one chain, each verified
separately.

| # | Defect | How it was established |
|---|---|---|
| **a** | `run_sse()` takes only `self`, but `run_mcp.py:118` calls `run_sse(host=…, port=…)` | `inspect.signature(...).bind()` → `TypeError: got an unexpected keyword argument 'host'`. **The whole `--transport sse` path raised before binding anything.** |
| **b** | `_build_server()` never forwards `host`/`port` to the constructor | AST of the call: kwargs are `state_manager`, `scheduler`, `composite_tools_enabled` only. `--host`/`--port` reached nothing. |
| **c** | The `--allow-remote` + mandatory-key guard lives only in the CLI | `WeebotMCPServer(host="0.0.0.0")` then `run_sse()` produced `settings.host == "0.0.0.0"`, `token_verifier None`, `auth None` — an unauthenticated server on every interface, with the CLI bypassed. `examples/04_mcp_server_demo.py` documents exactly this construction. |
| **d** | Both SSE tests could not fail | They build `MagicMock()` + a bare `AsyncMock()`, which accepts any signature. |
| **e** | `token_verifier` was passed **without** `auth=` | `FastMCP.__init__` raises `ValueError("Cannot specify auth_server_provider or token_verifier without auth settings")`. Setting `WEEBOT_MCP_API_KEY` made the constructor raise. |
| **f** | `_APIKeyTokenVerifier.verify_token` returned `bool` | The `TokenVerifier` protocol requires `AccessToken \| None`, and `BearerAuthBackend.authenticate` reads `.expires_at` and `.scopes` off the result — so a **valid** key raised `AttributeError`, an invalid one was rejected correctly. |

Pinned to `mcp==1.28.1` (`requirements.txt:106`), the version installed.

### The compounding that makes this more than a list

**(e) makes every guard that demands a key unsatisfiable.** `run_mcp.py`'s
`--allow-remote` branch requires `WEEBOT_MCP_API_KEY` before allowing a remote
bind — and setting it made `_build_server()` raise. So the one path that took
security seriously was guaranteed to fail, while the path that did not
(constructing the server directly) worked and was unauthenticated.

**(d) is why none of this was noticed.** `[VF]` and worth stating precisely,
because the obvious remedy does not work:

| Mock | Catches `run_sse(host=…)`? |
|---|---|
| `MagicMock()` + `AsyncMock()` | ✗ |
| `AsyncMock(spec=WeebotMCPServer.run_sse)` | ✗ |
| `MagicMock(spec=WeebotMCPServer)` | ✗ |
| `create_autospec(WeebotMCPServer, instance=True)` | ✓ |

**`spec=` constrains which attributes exist, not how they are called.** Only
autospec binds the real signature. That generalises past this file.

And `tests/unit/mcp/test_mcp_auth.py` asserted `verify_token(...) is True` —
**the suite encoded (f) as the expected contract.** The tests did not merely
miss the defect; they held it in place.

### Fixes

| # | File | Change |
|---|---|---|
| 1 | `mcp/server.py` | `verify_token` returns `AccessToken \| None` (f) |
| 2 | `mcp/server.py` | Pass `auth=AuthSettings(...)` alongside `token_verifier` (e) |
| 3 | `mcp/server.py` | `run_sse(host, port)`; refuse a non-loopback bind without a key (a, b, c) |
| 4 | `test_run_mcp.py` | `create_autospec` in place of bare mocks (d) |
| 5 | `test_mcp_auth.py` | Assert the protocol instead of the defect |

**The guard belongs where the socket is bound, not in the CLI.** That is the
single design decision here: `run_mcp.py` could only protect callers who went
through `run_mcp.py`, and the example the repo ships does not.

The auth URLs are advertised metadata for the `WWW-Authenticate` header, not
part of the check; a static shared key has no real issuer. They are derived from
the bind address. A later `run_sse(host=…)` does not update them, which affects
only what clients are told — never whether a token is required.

### Proof — behavioural, not structural

W6's own R-1 conceded its D45 proof *"assert[s] on source structure, not
behaviour… A live WebSocket test against a configured app is the right proof and
was not written."* This one is written, driving the real Starlette app through
`TestClient`:

| Request | Result |
|---|---|
| No `Authorization` header | **401**, `WWW-Authenticate: Bearer` |
| Wrong bearer token | **401** |
| Correct bearer token | **400** — past auth, failing on an empty body |

Before the fix the third case was a 500 from `AttributeError: 'bool' object has
no attribute 'expires_at'`.

> **Note for anyone extending these tests:** do not `GET /sse` with a valid
> token. It opens a server-sent-event stream that never closes and the test
> hangs. `POST /messages/` exercises the same `RequireAuthMiddleware` and
> returns. Also set `base_url` to a loopback origin — FastMCP auto-enables
> DNS-rebinding protection for loopback binds, and `TestClient`'s default
> `http://testserver` Host is rejected before auth is reached.

**Red before green, per file:**

| File | Original `server.py` | Fixed |
|---|---|---|
| `test_d47_sse_transport_auth.py` | 1 error (no `_LOOPBACK_HOSTS`) | **16 passed** |
| `test_mcp_auth.py` | 3 failed, 1 passed | **4 passed** |
| `test_run_mcp.py` | 2 failed, 12 passed | **14 passed** |

The two `test_run_mcp.py` failures are `TypeError: got an unexpected keyword
argument 'host'` — the exact production error the bare mocks could not see.

## D50 — the routing rule is deliberate, and says so

The claim is accurate as a description and wrong as an accusation.

`[VF]` **`session_id == "" ⇒ global` is a documented contract.**
`SessionPresenceEvent`'s own docstring:

> *"that field is the transport correlation id (`SessionScopedEventBus` stamps
> it, the broadcaster routes on it — empty means "global", non-empty means "this
> session's socket only"). A rail watching every session needs this on the
> global channel, so the subject session lives in `about_session_id` instead and
> `session_id` is left empty."*

So a fix that stopped broadcasting unscoped events would break a feature that
depends on the route, not close a leak.

**W6's R-2 was half right.** Its premise held — the broadcaster does fan
unscoped events to every global connection. Its conclusion did not:

- `[VF]` Flow events **are** stamped. The web path builds flows through
  `task_runner._factory` (`:376`) and `di.build_chat_flow` (`:438`), both of
  which wrap the bus in `SessionScopedEventBus`. `routers/sessions.py:279` feeds
  the former.
- `[VF]` `test_event_broadcaster_wiring.py` already proves a session-scoped
  event does **not** reach the global socket.
- `[VF]` A static sweep found **89** event constructions in `weebot/` that omit
  `session_id` — all inside flows and agents that receive a scoped bus. The
  design works; it is the enforcement that is conventional.

### The one thing worth fixing

`broker_adapter._convert`'s catch-all branch built
`NotificationEvent(text=f"[{event_type}] from {agent_id}: {str(data)[:200]}")`
with **no `session_id`** — up to 200 characters of the caller's arbitrary
payload, routed by the rule above to every authenticated `/ws` client. The
`fact_discovered` branch directly above it already did `data.get("session_id")`;
the fallback did not.

`[VF]` **Latent, not live.** `EventBrokerAdapter` is constructed nowhere in
`weebot/` — only in `tests/integration/test_event_bridge_contract.py`. Its
intended consumer, `WorkingMemory(event_publisher=…)`, is never built with a
publisher either. This is a hole closed before anyone fell in it.

Fix: propagate `session_id` from `data`, matching the branch above. Five lines.

## Phase 8 — coverage & residual risk

### Not covered

- **No live socket was bound.** Every D47 test drives the ASGI app in-process
  or stubs `run_sse_async`. That is a far stronger proof than W6 managed, but it
  is still not a real client against a real listener.
- **D48 remains uninvestigated** — the third W6 candidate (dynamic tools forward
  unvalidated `**kwargs` to `tool.execute()`). It was not Priority 1 and was not
  entered.
- **The `--allow-remote` CLI flag was left as it is.** It is now redundant with
  the bind guard rather than wrong, and removing a documented flag is a
  behaviour change beyond this scope.
- **The 89 unstamped constructions were not audited individually.** They were
  established as a class — all inside scoped-bus consumers — not one by one.

### Residual risks

- **R-1 — the stamping invariant is conventional, not enforced.** 89 event
  constructions depend on receiving a `SessionScopedEventBus`, and nothing
  fails if a future flow is wired with a raw bus. The failure mode is
  fail-open: an unstamped content-bearing event goes to every global listener.
  An allowlist of globally-routable event types at the broadcaster would close
  this, but it changes a documented contract and was out of scope here.
- **R-2 — `_convert` cannot invent scope.** A caller that omits `session_id`
  still produces a globally-routable event. The converter propagates what it is
  given; asserted explicitly rather than left implicit.
- **R-3 — MCP auth is a static shared key.** No rotation, no expiry
  (`expires_at=None`), no scopes. Appropriate for a single-operator local tool,
  and now honestly reflected in an `AccessToken` — but it is not an
  authorisation model.
- **R-4 — the bind guard trusts `settings.host`.** Binding `0.0.0.0` is
  refused, but a host that resolves off-machine by another spelling (a LAN IP,
  a hostname) is not loopback and so requires a key — correct — while an
  exotic loopback alias (`127.0.0.2`) is *not* in the allowlist and would be
  refused without a key. Conservative in the safe direction.

### Verdict

**COMPLETE for D47, CLEARED for D50.** D47 was six chained defects that together
meant MCP SSE authentication could not work in any configuration; it now works,
proven on the wire. D50's claim describes a deliberate documented contract, and
is recorded as cleared with its innocence argument — with one latent
payload-scoping hole fixed on the way past.
